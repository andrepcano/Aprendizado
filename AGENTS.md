# Regras do projeto

## Alterações de arquivos

- Antes de criar, editar, mover, renomear ou excluir arquivos, peça confirmação ao usuário.
- Após uma confirmação, altere somente os arquivos e pastas que fazem parte do pedido.
- Informe claramente o que foi alterado e aguarde a revisão do usuário quando solicitado.
- Antes de qualquer alteração, mostre alternativas, aguarde a escolha do usuário e peça uma confirmação final explícita antes de editar qualquer arquivo.

## Exercícios Python

- Ao separar exercícios, copie o código exatamente como está no arquivo-fonte, sem corrigir, resumir ou refatorar, a menos que o usuário peça isso explicitamente.
- Mantenha um exercício por arquivo e inclua o enunciado original como comentário no início, quando ele existir.
- Salve os arquivos em UTF-8.
- Antes de finalizar, revise a estrutura, os arquivos criados e a fidelidade da cópia ao arquivo-fonte.

## Verificação Python

- Após editar um arquivo `.py`, execute uma verificação de sintaxe quando o Python estiver disponível.
- Se houver erro, avise o usuário e explique onde está o problema.
- Sempre que o usuário pedir para fazer alguma mudança no código mostre as alternativas para o usuário ver se aceita a alteração ou quer que você mude algo ou rejeita

## Git e GitHub

- Não faça commits, pushes ou outras publicações sem solicitação explícita.
- Mantenha `.idea/` e `.codex/` fora do GitHub por meio do `.gitignore`.
